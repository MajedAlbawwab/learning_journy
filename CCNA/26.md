## IPv6 / The Binary Conversion
<span style="color:#e07b39">Internet Protocol Version 6</span>:

- relevant to IPv4
- based in <span style="color:#3b82f6">128 bits</span> in total length
- leads to 340 undecillion addresses
- IPv6 packet has a <span style="color:#3b82f6">header</span> of 40 bytes
- many new fields added, others removed instead
    - <span style="color:#3b82f6">version</span>: 6 (0110)
    - <span style="color:#3b82f6">traffic class</span> & <span style="color:#3b82f6">flow label</span>: <span style="color:#3b82f6">QoS</span>
    - <span style="color:#3b82f6">payload length</span>: just the length of the payload
    - <span style="color:#3b82f6">next header</span>: replaces the protocol number
    - <span style="color:#3b82f6">hop limit</span>: replaces <span style="color:#3b82f6">TTL</span>
    - Src. & Dst Addresses

![[Pasted image 20261122060127.png]]
You can see the version part in the header tells what version is used, 4 or 6.
But the computer only understands <span style="color:#3b82f6">binary</span>, so if you want to convert the number 6 to binary you make a <span style="color:#e07b39">stair of numbers</span>:
1 2 4 8 16 32 64 128 256....
The numbers you need to make 6 are <span style="color:#22c55e">2 + 4</span>, so these two numbers will be the 1 and the rest will be zero. You stop the binary number based on how much the part needs, so the version part in the header takes 4 <span style="color:#ef4444">(for both the image is wrong)</span> bits, so the answer will be (0110).

### IPv6 Address Structure
IPv6 <span style="color:#22c55e">example</span>:
<span style="color:#22c55e">2001:DB80:0000:0000:0001</span>
You can notice it's <span style="color:#3b82f6">hexadecimal</span> and uses colons instead of dots.
Every <span style="color:#3b82f6">octet</span> is 16 bits, so this means every character in the octet is 4 bits.
To convert every character to binary we will use the <span style="color:#e07b39">stair number method</span>, and the limit we stop at is 4 bits because every character is 4 bits.
A = 10 B = 11 C = 12 D = 13 E = 14 F = 15

### IPv6 Address Compression
The IP can be simpler:
2001:DB80:0000:0000:0000:0000:0000:0001
If an octet has zeros, you can write only the number and drop all the zeros on the left, so it can be:
<span style="color:#22c55e">2001:DB80:0:0:0:0:0:0001</span> or:
<span style="color:#22c55e">2001:DB80:0:0:0:0:0:1</span>
If you have octets that are all zeros, you can leave them out and only put a <span style="color:#3b82f6">double colon</span>, so it can be:
<span style="color:#22c55e">2001:DB80::0001</span> or:
<span style="color:#22c55e">2001:DB80::1</span>
<span style="color:#ef4444">IMPORTANT: the IP can't have two double columns, only one</span>
The questions in CCNA can be that he gives you an IP and tells you which compression is correct.

### IPv6 Address Types
- different types are supported
- to help with private/public addressing
- ::1/8 <span style="color:#3b82f6">loopback address</span>
- 2000::/3 <span style="color:#3b82f6">global unicast address</span>
- FC00::/7 <span style="color:#3b82f6">unique local unicast address</span>
- FE80::/10 <span style="color:#3b82f6">link-local unicast address</span>
- FE00::/8 <span style="color:#3b82f6">multicast address</span>

IPv6 supports:

- <span style="color:#e07b39">unicast</span>: (one-to-one)
- <span style="color:#e07b39">multicast</span>: (one-to-many)
- <span style="color:#e07b39">Anycast</span>: (one-to-nearest)

IPv4 supports this also, with <span style="color:#3b82f6">broadcast</span>, which IPv6 doesn't support.

### IPv6 Interface ID
When you enable IPv6 on a device like a router, for example, the IP will be unique. How?
Since the device has a <span style="color:#3b82f6">MAC address</span> and that MAC address is unique, the device will use a method called <span style="color:#e07b39">EUI-64</span>, which will make an IPv6 based on the MAC.
<span style="color:#22c55e">MAC example: 3C:5A:B4:1F:7D:92</span>

1. Split the MAC
    - 3C:5A:B4 1F:7D:92
2. Put FF and FE in the middle
    - 3C:5A:B4:FF:FE:1F:7D:92
3. FF goes in the left, FE in the right
    - 3C:5A:B4FF:FE1F:7D:92
4. You're gonna take the second hex digit (C) in the left and convert it to binary, then you're gonna flip the second digit from the right. C = 12, so in binary it will be 1100, and after the flip it will be 1110, so we return this number to hexadecimal again, so it becomes (E)
    - 3E:5A:B4FF:FE1F:7D:92
5. We put FE80:: in the first, then we put the rest and we join the parts so every part has 4 digits
    - Answer = FE80::3E5A:B4FF:FE1F:7D92

Other <span style="color:#22c55e">examples</span>:
<span style="color:#22c55e">7A:2D:E1:09:C4:5B = FE80::782D:E1FF:FE09:C45B</span>
<span style="color:#22c55e">0012:3456:ABCD = FE80::0212:34FF:FE56:ABCD</span>
