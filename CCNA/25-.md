## IPv4 Classes (important to remember)

| Class   | Prefix | Start Address | End Address     |
| ------- | ------ | ------------- | --------------- |
| Class A | /8     | 1.0.0.0       | 126.255.255.255 |
| Class B | /16    | 128.0.0.0     | 191.255.255.255 |
| Class C | /24    | 192.0.0.0     | 223.255.255.255 |
| Class D | /8     | 224.0.0.0     | 239.255.255.255 |
| Class E | /8     | 240.0.0.0     | 255.255.255.255 |

## IPv4 Types

<span style="color:#e07b39">Private</span> vs <span style="color:#e07b39">public</span> IPv4 Addresses:
- avoid duplication
- <span style="color:#e07b39">Private</span>: available and free (used only in <span style="color:#3b82f6">LAN</span>)
- <span style="color:#e07b39">Public</span>: reserved, costs money

Private Addresses <span style="color:#3b82f6">RFC 1918</span>: (important to remember)
- 10.0.0.0 - 10.255.255.255 /xx
- 172.16.0.0 - 172.31.255.255 /xx
- 192.168.0.0 - 192.168.255.255 /xx

## The P2P Subnet
If the <span style="color:#3b82f6">subnet mask</span> is 31, that will make the <span style="color:#3b82f6">network ID</span> and the <span style="color:#3b82f6">broadcast ID</span> the only IPs available, so these two IPs can connect <span style="color:#3b82f6">P2P</span>.
If the subnet mask is 30, that will make 4 IPs, so there will be 2 usable IPs but with <span style="color:#3b82f6">broadcast</span> technology.

## Classless Inter Domain Routing (CIDR):
- design a <span style="color:#3b82f6">subnet mask</span>
- based on the need
	- need for amount of address space
	- factor of safety (future growth)
	- appropriate isolation
	- <span style="color:#ef4444">careful with summarization</span>

So now you need to design the subnet mask. You will get a number of hosts or endpoints, and you need to know what is the best subnet mask for this number of hosts.

<span style="color:#22c55e">For example, if you have a building that has 4 floors:</span>
- <span style="color:#22c55e">the first needs 50 hosts</span>
- <span style="color:#22c55e">the second needs 14</span>
- <span style="color:#22c55e">the third needs 30</span>
- <span style="color:#22c55e">the fourth needs 5</span>

For best practice you need to design from the bigger to the smaller hosts, so like 50-30-14-5.

Now you need to make a <span style="color:#e07b39">stair of multiples</span>, like this:
1-2-4-8-16-32-64-128-256-512-1024-2048....
Then you need to stop at the number that can contain your need for hosts. So if our need now is 50 hosts, we will stop at 64. All the numbers before 64 are the zeros of the subnet mask, so now we have 6 zeros.

To get the subnet mask you need to subtract: 32-6 = 26 (that is our subnet).
The <span style="color:#3b82f6">increment value</span> is the same number we stopped at in the stairs (64).
![[Screenshot_50.png]]

So, for the next floor the <span style="color:#3b82f6">Network ID</span> will be 192.108.1.64, because the first floor ended with 63.

<span style="color:#22c55e">Example for the next floor, you can see we added the IV on the IP:</span>
<span style="color:#22c55e">64 + 32 = 95 (the zero as one)</span>
We can choose more than 32 if we want a safety factor.
![[Screenshot_51.png]]

So the third floor will start at 192.168.1.96.
![[Screenshot_52.png]]

So the fourth floor will start at 192.168.1.112.
![[Screenshot_53.png]]

So we started at 192.168.1.0 and we end at 192.168.1.119.

From .120 to .255 is unused: 255 - 120 = 134.

If we used the old <span style="color:#3b82f6">subnet classes</span> it would take us 1048 IPs.
